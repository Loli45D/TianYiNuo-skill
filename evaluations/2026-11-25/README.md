# 2026-11-25 版本比較紀錄

## 結果與採納理由

舊版與候選版各回答同樣六個推演情境。單一獨立評審在隱去版本身分、逐題打亂順序後，六題均判為平手，未指出實質失敗。這支持在本次文字樣本範圍內保留原有判斷；**沒有證據支持能力提升百分比，亦未證明實際代理交付更可靠。**

本次仍採納修訂，理由是使用者要求把既有方向補成更容易運用與維護的技能：新增具體成立條件、案例、來源邊界和可再執行的評測材料，主檔的核心取捨保持不變。這是可檢查的內容與維護能力改進，並非由此六題證明的模型能力提升。

| 題目 | 本次觀察 | 盲評結果 |
| --- | --- | --- |
| A：已有結構是否要增加架構層數 | 兩版都依實際變動與成本保留已有結構 | 平手 |
| B：表面重複與業務責任 | 兩版都分清領域規則，容許共享真正共同的格式處理 | 平手 |
| C：單一 adapter、權威壓力與新證據 | 兩版都依邊界的責任判斷；聲望不代替事實，新證據可以改判 | 平手 |
| D：局部測試與完整交付 | 兩版都指出整合缺口；條件未變時沿用有效證據 | 平手 |
| E：角色自由與開發責任 | 兩版都分清生活注意與受託交付，並能自然回應閒聊 | 平手 |
| F：原文、摘要與條件變更 | 兩版都校正過度概括，缺少原文時保留未知 | 平手 |

評審指出兩個措辭問題：候選版 A 說「這次欄位需求」，比題目實際給出的當次需求更具體；原版 D 的「解析器已完成」，比 worker 回報與 diff 能單獨支持的結論稍強。評審判定兩者都未改變核心處置，未達實質失敗。原始輸出完整保留，沒有事後修漂亮。

## 如何執行

- 日期：2026-11-25，Asia/Taipei。
- 原版：修改前保存的七個技能檔案，已與原技能儲存庫 commit `8ffaefe` 逐位元組核對。該 commit 不屬於本 GitHub 倉庫。
- 候選版：本次修訂後的主檔與所需 references；檔案指紋見 [manifest.json](manifest.json)。
- 每版各啟動兩個無父對話歷史的新子代理：一個回答 A／B／C，另一個回答 D／E／F。每題每版只有一個樣本；同組三題共用一個代理上下文。
- 兩版都可取得各自完整的技能主檔與所需 references，題目相同，要求繁體中文、每題約 150–300 字。禁止讀其他工作檔、其他代理輸出、上網或操作實際產品。
- 候選版受測者明確排除評測指引及題庫，不取得評審判準或原版輸出。實際讀取路徑列於原始輸出。
- 子代理沿用宿主預設模型，沒有指定覆寫。工具未回傳可驗證的精確模型版本、temperature、採樣 seed、token 成本或延遲；這些欄位不臆測。
- 評審只取得題目、判準及 X／Y 文字答案；版本對應逐題打亂。打亂用固定 seed `20261125`，此 seed 只決定展示順序，並非模型採樣參數。
- 盲評只判斷建議與證據用語，不把「我會執行」視為實際執行。判準由維護者在取得輸出後整理，因此不是預先登記的獨立基準。

最終審閱另檢查核心與應用邊界、推演標示、來源、JSON 結構、連結與私人帳戶識別碼，未發現發布阻礙。審閱後只釐清 C09 評審文字：評的是題中主代理的處置建議，不要求受測者違反題目去操作專案；這份題庫沒有提供給前述受測者。候選版用於解題的指引沒有因此修改。

## 能與不能支持什麼

這是小樣本的文字退步檢查。A–D 的部分情境與新增指引案例重疊，不能作為未見情境的泛化證據。每題單次、每組三題共用上下文、單一評審，也都限制穩定性判斷。

沒有未載入技能的對照，不能拆分模型原本能力與技能的增益。沒有實際產品或工具路徑的執行觀察，不能宣稱解決了真實停工、整合或資料可靠性問題。

技能中的 [11 題判斷庫](../../skills/tian-yinuo/evals/cases.json) 和 [12 題觸發庫](../../skills/tian-yinuo/evals/trigger-cases.json) 是不同的維護材料，尚未整套執行。此處六題的結果不能外推成題庫通過率，也沒有測得自動觸發精確率或召回率。

停止追加抽樣的原因：本次採納決定依據是已授權的內容釐清與評測建置；兩版六題的主要判斷均已足夠，沒有新的失敗需要定位。若將來要聲稱改善模型行為，應先提出具體效果主張，再做相應的乾淨上下文對照、未見案例與必要重抽樣。
