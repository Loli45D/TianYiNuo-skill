# 田以諾設計判斷技能

依田以諾已表達的目的、價值與取捨，判斷一件事怎樣做更合理。從理由重新推導，檢查舊結論的成立條件，也允許形成有根據的新做法。

本版保留原有設計方向，補上具體案例、可選用的方法與維護用評測。核心取捨決定方法怎樣使用；工具、流程與外部技能的聲望不代替判斷。

## 適合的用途

- 評估程式、模組、資料與介面的責任安排，決定哪些結構值得保留或改動。
- 評審小花音／Kohane／CoreNE 的認知、記憶、主體性與生活體驗設計。
- 診斷 Codex／Work／Dot 在已授權任務中的停滯、局部交付、過度驗證或來源混淆。
- 維護這套判斷方法，檢查修訂有沒有改善對應情境。

日常聊天、單純文字替換與普通語法修正，不因出現相關人名或專案名就擴成完整設計評審。使用技能時保留原助手的身份與口吻。

## 使用

在支援這種 `SKILL.md` 技能套件的工具中，把 `skills/tian-yinuo` 的完整目錄加入該工具指定的技能位置。保留 references、evals、agents 與 assets 的相對位置；安裝入口與自動選取方式依所在工具而定。

已註冊名為 `tian-yinuo` 的技能時，可明確要求：

> 使用 $tian-yinuo，評估這份設計。先說值得保留什麼，再找出會影響目的的問題與相稱的改法。

> 用田以諾判斷：這個 adapter 隱藏了什麼責任？拿掉後，複雜度會消失還是回到呼叫端？

> 依田以諾評審小花音的記憶設計，分清經歷、後來的理解，以及現在的選擇。

提供實際需求、方案、受影響的路徑及已知證據，比要求套固定評分模板更有用。資訊不足時，技能應指出會改變結論的缺口，並保留有條件的建議。

## 2026-11-25 版增加什麼

1. **具體判斷方法。** 區分同名異義，沿實際變動看責任；以移除後的後果評估抽象，只在重要取捨不清時比較不同介面。
2. **有成立條件的例子。** 涵蓋表面重複、已足夠的結構、單一實作仍有價值的邊界，以及新證據如何改變結論。
3. **對應症狀的工作修正。** 按已觀察的失敗選擇指引形式；分清解析器通過與真正功能交付，按版本及條件決定是否需要再次驗證。
4. **維護用評測。** 分離題目、判準與觀察結果，允許多種合理答案，保留平手、未知與停止條件。

公開方法的來源及採用範圍見 [依據與適用範圍](skills/tian-yinuo/references/source-basis.md)。本倉庫使用自行編寫的說明和推演案例，沒有整包複製外部技能。
