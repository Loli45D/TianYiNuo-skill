# 技能維護用評測

**只在建立、修改或驗證本技能時讀。** 日常使用不增加評測關卡。本頁比較判斷與行為是否改善；案例存在、檔案可解析或技能已讀取，都不能證明技能有效。

## 題目與判準分開

- `evals/cases.json`：11 個推演題。受測者只取得所選 `inputs` 的 `prompt` 與指定技能版本；`rubrics` 留給評審。各題包含可觀察判準、實質失敗和多種合理方向，沒有指定台詞。
- `evals/trigger-cases.json`：12 個未執行的觸發題。只向受測者提供題目及相同的可用技能描述集合；`expectations` 留給評審。它區分顯式指定、依當前任務選擇及不適用情境。

這些是合成情境，不是私人聊天、共同回憶或已完成的實測。將來的執行結果另存，不能把題目預期當成結果。

## 同題比較原版與候選版

修改前保存原版與想解決的具體問題；兩版使用相同題目、任務材料、模型和可取得設定。每份輸出從乾淨上下文開始，只提供當地需要的資料，隔離其他版本輸出、判準、作者結論及先前評語。不能取得乾淨上下文時，記錄限制，縮小比較主張。若要判斷技能比一般能力多帶來什麼，再加未載入技能的對照。

觸發測試觀察模型是否選擇並讀取技能，不預先強制載入正文。指定技能解題則檢查輸出與可取得的行為證據：選擇、理由、產物及驗證是否實際運用相應取捨。已讀、引用名詞或聲稱遵守，都不能代替這層觀察；不要求不可見的思考內容。

## 評審理由，不評口號

先逐題核對可觀察判準，標記「有支持／有反證／未觀察到」，附對應輸出或行為證據。不可接受的失敗須確實發生，不能因答案沒有逐項複述判準就判失敗。合理方向是例子；其他有根據且滿足目的的答案同樣可成立。

再把兩份輸出隱去版本身分、打亂順序盲評，允許 A 較好、B 較好、平手或證據不足。說明差異改善了哪個實際結果。語氣相似、字數較少或迎合作者，不自動較好；兩版都足夠時可保留原版。不要用關鍵字、regex 或漂亮總分代替哲學判斷。

## 泛化、重抽樣與停止

保留未用於修改的案例，待版本固定後才交給受測者；維護者已反覆看過的本包題目不能冒稱未見過案例。可請獨立評審依同一目的另出變體，保留其中一部分，不先提供預期結論。

抽樣量依觀察決定：明確反例先定位原因；結果波動、接近平手或評審不一致時，再做乾淨上下文的成對重抽樣。記錄每份原始輸出，不只留下較好的一次；不為湊固定次數重跑已沒有新資訊的檢查。

當目標問題已有對應證據、受影響情境未見實質退步，且剩餘不確定性不再改變採納決定，就停止。若工具、樣本或上下文限制使判斷不足，交代限制；只能證明文字更清楚時，就只宣稱文字釐清。

## 最小記錄

記錄日期、案例 ID 與內容 hash、兩版技能的 commit 或檔案 hash、模型與可取得設定、實際提供的上下文、原始輸出及行為證據、逐題判斷與盲評理由、重抽樣及停止原因。未知設定寫未知；沒有執行就記未執行。版本應涵蓋實際使用的相關 references，不能只記主檔。

沿用現有對話、可用子代理及檔案工具即可，不新增外部 CLI、API key 或套件。方法取自 Anthropic 的對照／評審／比較分工與 Superpowers 的模式、應用、反例題型；來源見 [依據與適用範圍](source-basis.md)。此處按判斷技能的需要採用，不增加固定輪數或日常交付儀式。
